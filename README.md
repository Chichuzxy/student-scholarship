# 学生成绩与奖学金评定系统（Java）

Java 程序设计课程综合作业的重构版。原作业是一个 277 行的单文件过程式程序，
本版拆成 4 个职责清晰的类，把评定规则抽出来，并补了 21 条自测用例。

## 功能

- 学生录入：班级、学号、姓名、5 门课成绩、操行分；构造时校验取值（0-100）、学号非空
- 总分 / 最低单科 / 平均分：由实体自己算，不散落在业务代码里
- 排序：按总分降序，总分相同按学号升序（结果稳定可复现）
- 奖学金评定：按等级顺序逐个判定，命中高等级后不再参与低等级（每人只评一次）
- 统计：全体平均分、全部科目及格率
- 输出：打印到控制台，同时写 `report.txt`（UTF-8）

## 目录

```
src/edu/scvtc/scholarship/
  Student.java              实体：数据 + 派生计算（总分/最低单科/平均分）
  ScholarshipRule.java      规则：某等级要求「单科 >= X 且操行 >= Y」
  StudentService.java       业务：录入、排序、评定、统计、查询
  Main.java                 命令行入口 + 演示数据
  StudentServiceTest.java   自测用例（零外部依赖）
```

## 运行

需要 JDK 8 及以上。Windows：

```bat
set JAVA_HOME=C:\path\to\jdk
build.bat        :: 编译
run-tests.bat    :: 跑 21 条用例
run.bat          :: 跑演示并生成 report.txt
```

手动命令：

```bash
javac -encoding UTF-8 -d out src/edu/scvtc/scholarship/*.java
java -cp out edu.scvtc.scholarship.StudentServiceTest
java -cp out edu.scvtc.scholarship.Main
```

## 相对原作业改了什么

原版 `ztz.java`（277 行，单文件）有三个问题：

1. **每个等级只评一个人**：`getGrade()` 里找到第一个符合条件的人就 `break`，
   打印时同理，导致名单永远只有 1 人。本版改成对每个学生遍历规则、命中即停，
   学生维度只评一次。
2. **排序名不副实**：写的是冒泡排序，实际是比较交换的选择排序；而且没有处理
   总分相同的情况，结果不可复现。本版用 `Comparator` 指定「总分降序 + 学号升序」。
3. **数据与逻辑耦合**：10 条学生数据硬编码在方法体里，评定、打印、录入全在一个类中。
   本版把数据挪到 `Main` 的演示构造，业务类不碰控制台，测试可以直接调。

## 已知取舍

一等要求「单科 >= 90」，所以总分最高但有一门 89 分的学生只能拿二等
（示例数据里 01 号总分 478 却评二等，06 号总分 472 评一等）。
这是规则本身的结果，不是 bug。如果学校更看重总分，应改 `ScholarshipRule`
的 `minSubjectScore` 或改成「按总分排名」方案——规则外置就是为了这种调整。
